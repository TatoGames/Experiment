# 동네 카페 타이쿤 기획서

> 웹 브라우저에서 실행되는 클릭형 경영 시뮬레이션. HTML/CSS/JavaScript만 사용, 빌드 도구 없이 `index.html`을 열면 실행.
> 파일: `index.html`, `style.css`, `game.js`

## 1. 컨셉

- **소재**: 동네 골목의 작은 카페를 키우는 타이쿤. 플레이어는 사장이 되어 커피를 팔고, 직원·장비를 늘려 체인 카페로 성장시킨다.
- **재화**: 코인(₩ 표기). 단일 재화만 사용한다(MVP).
- **분위기**: 따뜻한 갈색/크림 톤, 큼직한 "커피 팔기" 버튼 하나가 화면 중심.
- **MVP 범위**: 클릭 수입, 자동 수입, 업그레이드 구매, localStorage 저장/불러오기, 오프라인 수입.

## 2. 핵심 루프

1. **클릭 수입**: "커피 팔기" 버튼을 누를 때마다 클릭당 수입만큼 코인을 얻는다.
2. **자동 수입**: 업그레이드(아르바이트생 등)를 사면 초당 수입이 생겨 클릭하지 않아도 코인이 늘어난다.
3. **업그레이드 구매**: 모은 코인으로 업그레이드를 구매한다. 보유 수가 늘수록 가격이 오른다.
4. **다음 단계 해금**: 누적 수입이 단계 조건을 넘으면 다음 성장 단계가 열리고 새 업그레이드가 해금된다. 다시 1번으로.

## 3. 경제 수치표

### 3.1 기본값

| 항목 | 값 |
|---|---|
| 시작 자금 | 0 코인 |
| 클릭당 기본 수입 | 1 코인 |
| 가격 증가율 (공통) | ×1.15 |
| 게임 틱 | 100ms (수입은 `초당수입 × dt`로 누적, dt는 실제 경과 시간) |
| 숫자 표시 | 정수는 그대로, 1,000 이상은 `1.2K`, `3.4M` 식 축약. 내부 계산은 소수 허용, 가격만 `floor` |

### 3.2 업그레이드 (5종)

| id | 이름 | 기본 가격 | 효과 (1개당) | 해금 단계 |
|---|---|---|---|---|
| `bean` | 고급 원두 | 30 | 클릭당 수입 +1 | 1 |
| `part` | 아르바이트생 | 50 | 초당 수입 +1 | 1 |
| `machine` | 에스프레소 머신 | 300 | 초당 수입 +8 | 2 |
| `showcase` | 디저트 쇼케이스 | 1,500 | 초당 수입 +40 | 3 |
| `coupon` | 단골 쿠폰 | 5,000 | 모든 수입(클릭+자동) 배율 +5%p | 3 |

해금 단계 표기는 5장 성장 단계와 맞춘다. 해금 전 업그레이드는 화면에 잠금 상태로 표시하거나 숨긴다.

### 3.3 계산식

`owned[id]`는 해당 업그레이드의 보유 수.

- 구매 가격: `price(id) = floor(basePrice[id] × 1.15 ^ owned[id])`
- 배율: `multiplier = 1 + 0.05 × owned.coupon`
- 클릭당 수입: `perClick = (1 + owned.bean) × multiplier`
- 초당 수입: `perSecond = (owned.part × 1 + owned.machine × 8 + owned.showcase × 40) × multiplier`
- 구매 조건: `coins >= price(id)` 이고 해금된 업그레이드일 것. 구매 시 `coins -= price`, `owned[id] += 1`.
- 1회 구매 단위: 1개 (일괄 구매는 MVP 제외).

### 3.4 가격 예시 (검증용)

| 보유 수 | bean | part | machine | showcase | coupon |
|---|---|---|---|---|---|
| 0 | 30 | 50 | 300 | 1,500 | 5,000 |
| 1 | 34 | 57 | 345 | 1,725 | 5,750 |
| 5 | 60 | 100 | 603 | 3,017 | 10,056 |
| 10 | 121 | 202 | 1,213 | 6,068 | 20,227 |

## 4. 저장 규칙

| 항목 | 값 |
|---|---|
| localStorage 키 | `taikun_cafe_save_v1` |
| 형식 | JSON 문자열 |
| 자동 저장 주기 | 10초마다 |
| 추가 저장 시점 | 업그레이드 구매 직후, 단계 해금 직후, `beforeunload`, 탭이 숨겨질 때(`visibilitychange`) |
| 불러오기 | 페이지 로드 시 1회. 키가 없거나 JSON 파싱 실패, `version`이 다르면 새 게임으로 시작(깨진 데이터는 덮어쓰기 전 무시) |
| 초기화 | "처음부터" 버튼, 확인창(`confirm`) 후 키 삭제 및 상태 리셋 |

### 4.1 저장 데이터 필드

| 필드 | 타입 | 설명 |
|---|---|---|
| `version` | number | 저장 포맷 버전. 현재 `1` |
| `coins` | number | 현재 보유 코인 |
| `totalEarned` | number | 누적 획득 코인 (단계 해금 판정용, 구매로 줄지 않음) |
| `stage` | number | 현재 성장 단계 (1부터) |
| `owned` | object | `{ bean, part, machine, showcase, coupon }` 각 보유 수(정수) |
| `lastSavedAt` | number | 저장 시각 `Date.now()` (ms) |

### 4.2 오프라인 수입

- **지급함**: 로드 시 `lastSavedAt`과 현재 시각 차이만큼 지급한다.
- **효율**: 50%
- **상한**: 8시간 (28,800초)
- **계산식**: `offlineSec = min(max(0, (now - lastSavedAt) / 1000), 28800)`
  `offlineEarned = perSecond × offlineSec × 0.5`
- 지급 후 `coins`와 `totalEarned`에 더하고, 1초 미만(`offlineSec < 1`)이거나 `perSecond == 0`이면 지급·안내를 생략한다.
- 지급 시 "자리를 비운 동안 N코인을 벌었어요" 팝업을 한 번 보여준다.
- 시계가 과거로 돌려져 차이가 음수면 0으로 처리한다.

## 5. 성장 단계·해금 조건

### 5.1 단계 요약

`stage`는 현재까지 해금한 최고 단계(정수 1~3)이며, 새 게임의 초기값은 `1`이다. `totalEarned`는 게임 시작 이후 지급된 수입의 누계다. 클릭·자동·오프라인 수입을 지급할 때 증가하고, 업그레이드 구매로 돈을 사용해도 감소하지 않는다. 아래 보유 수는 각 업그레이드 ID의 현재 보유 수를 의미한다.

| stage | 단계 이름 | 해금 조건(모두 충족) | 신규 해금 업그레이드 | 해당 단계에서 구매 가능한 업그레이드 | 단계 진입 효과 |
| --- | --- | --- | --- | --- | --- |
| 1 | 노점 | 조건 없음(시작 단계) | `bean`, `part` | `bean`, `part` | 기본 클릭 수입 및 `part` 자동 수입 사용 가능. 단계 자체 수입 배율 ×1. |
| 2 | 동네 카페 | `totalEarned >= 500` AND `part` 보유 수 `>= 3` | `machine` | `bean`, `part`, `machine` | `machine` 구매로 경제 수치표의 자동 수입 효과를 추가할 수 있음. 단계 자체 수입 배율 ×1. |
| 3 | 체인점 | `totalEarned >= 10000` AND `machine` 보유 수 `>= 3` | `showcase`, `coupon` | `bean`, `part`, `machine`, `showcase`, `coupon` | `showcase`의 자동 수입 효과와 `coupon`의 수입 배율 효과를 구매할 수 있음. 단계 자체 수입 배율 ×1. |

상위 단계는 하위 단계의 해금을 모두 유지한다. 조건을 충족하면 비용 없이 자동으로 다음 단계에 진입하며, 별도의 승급 버튼이나 승급 비용은 없다. 총 업그레이드 보유 수로 대체하지 않고, 2단계는 `part` 수, 3단계는 `machine` 수를 각각 확인한다.

### 5.2 경제 수치표·계산식과의 연결

3.2 경제 수치표의 해금 단계는 `bean=1`, `part=1`, `machine=2`, `showcase=3`, `coupon=3`으로 맞춘다. 기본 가격은 각각 30, 50, 300, 1500, 5000이며, 구매 가격은 기존 규칙인 `floor(기본 가격 × 1.15^해당 업그레이드 보유 수)`를 따른다. 단계가 올라가도 기본 가격·가격 증가율·개별 효과를 변경하지 않는다.

3.3 계산식의 수입 배율은 `coupon` 보유 효과로만 증가한다. 단계 해금 자체는 클릭 수입·초당 자동 수입·오프라인 수입에 추가 배율이나 일회성 수입을 주지 않는다. `coupon`이 해금되어도 구매하기 전에는 수입 배율이 증가하지 않는다. `machine`, `showcase`, `coupon`의 구체 효과 값은 3.2 및 3.3을 그대로 사용한다.

### 5.3 해금 판정 시점과 처리 순서

공통 해금 판정 함수를 다음 시점에 실행한다.

- 매 게임 틱: 해당 틱의 자동 수입을 잔액과 `totalEarned`에 반영한 직후.
- 업그레이드 구매 성공 직후: 잔액 차감과 보유 수 증가를 반영한 직후. 실패한 구매는 상태를 변경하지 않는다.
- 클릭 수입 지급 직후: 잔액과 `totalEarned`를 갱신한 직후.
- 저장 데이터 불러오기 완료 직후: 저장된 `stage`·`totalEarned`·업그레이드 보유 수와 기존 규칙에 따른 오프라인 수입을 반영한 뒤, 첫 화면을 갱신하기 전.

판정은 아래 순서로 수행한다. 한 번 호출할 때 가능한 승급을 모두 처리한다.

```text
if stage < 2 and totalEarned >= 500 and part 보유 수 >= 3:
    stage = 2
    2단계 해금 알림 표시

if stage == 2 and totalEarned >= 10000 and machine 보유 수 >= 3:
    stage = 3
    3단계 해금 알림 표시
```

판정 완료 후 단계명·구매 목록·잠금 조건 표시를 갱신한다. 구매 처리에서도 `stage >= 해당 업그레이드의 해금 단계`인지 검사해 잠긴 업그레이드는 구매할 수 없게 한다. 잠긴 항목에는 5.1의 해당 단계 해금 조건을 표시한다.

### 5.4 영구 해금과 저장

한 번 해금한 단계는 되돌리지 않는다. 판정 함수는 `stage`를 올리는 동작만 하며, 잔액 감소나 재접속으로 단계를 재계산해 낮추지 않는다. 새 게임 초기화 시에만 `stage=1`, `totalEarned=0`, 모든 업그레이드 보유 수 0으로 돌아간다.

4.1의 `stage`와 `totalEarned` 필드를 그대로 사용한다. 단계 변경 시 기존 저장 키 `taikun_cafe_save_v1`에 즉시 저장하고, 기존 10초 자동 저장도 유지한다. 불러온 `stage`가 이미 해금된 단계이면 같은 단계의 알림을 다시 띄우지 않는다. 불러오기 후 새 조건을 충족해 실제로 승급한 경우에만 알림을 표시한다. 오프라인 수입은 기존 효율 50%·최대 8시간 규칙을 유지한다.

### 5.5 해금 알림 문구

| 발생 시점 | 알림 문구 |
| --- | --- |
| `stage`가 1에서 2로 변경될 때 | 동네 카페 해금! 이제 커피 머신(machine)을 구매할 수 있어요. |
| `stage`가 2에서 3으로 변경될 때 | 체인점 해금! 이제 쇼케이스(showcase)와 쿠폰(coupon)을 구매할 수 있어요. |

알림은 실제 단계 변경마다 한 번 표시한다. 한 번의 판정으로 두 단계가 연속 해금되면 2단계, 3단계 순서로 표시한다.

### 5.6 확인 기준

| 입력 상태 또는 행동 | 기대 결과 |
| --- | --- |
| `stage=1`, `totalEarned=499`, `part=3` | 1단계 유지, `machine` 잠금 |
| `stage=1`, `totalEarned=500`, `part=2` | 1단계 유지, `machine` 잠금 |
| `stage=1`, `totalEarned=500`, `part=3` | 2단계 해금, `machine` 구매 가능, 알림 1회 |
| 위 조건에서 구매로 잔액이 500 미만이 됨 | `totalEarned`와 2단계 유지 |
| `stage=2`, `totalEarned=9999`, `machine=3` | 2단계 유지 |
| `stage=2`, `totalEarned=10000`, `machine=2` | 2단계 유지 |
| `stage=2`, `totalEarned=10000`, `machine=3` | 3단계 해금, `showcase`·`coupon` 구매 가능, 알림 1회 |
| 3단계 해금 후 `coupon` 미구매 | 단계 해금만으로 수입 배율 증가 없음 |
| 3단계를 저장한 뒤 재접속 | 3단계 및 해금 목록 유지, 기존 단계 알림 재표시 없음 |
